# Platform Architecture

> Лоуполи 3D ферма-сендбокс → платформа для пользовательских миров  
> Референсы: Roblox, Second Life, ArcheAge, Lineage 2, Genshin Impact  
> Подход: начать с конкретной игры, платформа вырастает органически

---

## Vision

Игрок попадает на спаун — карта с мирами. Часть миров от разработчика, часть от игроков. Можно зайти в любой мир, вернуться, перейти на другой. Каждый мир — отдельный сервер с своими правилами, физикой, жанром. Спаун — это тоже просто мир с флагом `official: true`.

Пользователь может поднять свой сервер и его мир появится в реестре. Переход одним кликом прямо из спауна.

---

## Стратегия разработки

```
Этап 1: конкретная игра (ферма)
    написать линейно, без абстракций
        ↓
Этап 2: extract & generalize
    попросить ИИ вытащить абстракции из живого кода
    захардкоженные значения → WorldConfig
        ↓
Этап 3: платформа
    контракт мира проверен реальным кодом
    пользователи получают те же инструменты
```

**Главное правило:** не проектировать абстракции до того как понял что конкретно нужно.

## Технический стек

| Слой                | Технология                | Причина                                         |
| ------------------- | ------------------------- | ----------------------------------------------- |
| 3D клиент           | Zig + raylib              | нативный C interop, WASM, стабильный тулчейн    |
| UI в игре (desktop) | Sciter                    | C API, полный CSS3/flexbox, ~5MB, не Chromium   |
| UI в игре (web)     | DOM поверх canvas         | Sciter не компилируется в WASM                  |
| Встроенный браузер  | Системный WebView         | Edge/WKWebView/WebKitGTK, нулевой размер        |
| Шейдеры             | GLSL (кастомные)          | cel-shading, bloom поверх raylib                |
| Web клиент          | Zig → WASM (Emscripten)   | тот же код, другой таргет                       |
| Бэкенд              | Go                        | горутины = много WS соединений, знакомый язык   |
| ТМА                 | JS / React + Telegram SDK | вайбкодится при готовом API                     |
| БД                  | PostgreSQL + Redis        | PostgreSQL — данные, Redis — онлайн-присутствие |
| DevOps              | Docker Compose            | dev окружение одной командой                    |

### Почему Zig, не Go для клиента

- raylib нативен для C → Zig вызывает напрямую через `@cImport`
- нет GC пауз (критично для игрового loop)
- WASM таргет встроен в компилятор
- Go остаётся для бэкенда где он сильнее

### Почему raylib, не Mach

- Mach требует номинированный nightly Zig — двойная нестабильность
- raylib работает со стабильным Zig 0.13.0
- огромная документация и примеры на C — ИИ знает хорошо
- проверен в продакшне, активно поддерживается

## Аккаунты и аутентификация

### Структура пользователя

```go
type User struct {
    ID           uuid.UUID
    Email        string
    PasswordHash string

    // опциональные привязки
    TelegramID   *int64    // nil если не привязан
}
```

### Стратегия входа

```
Основной вход:     email + пароль → JWT
Привязка TG:       в настройках → Telegram initData → TelegramID в User
Вход из ТМА:       Telegram initData → находим User по TelegramID → JWT
Гостевой аккаунт:  создаётся по TelegramID без email, потом апгрейд
```

Один JWT работает везде — в 3D клиенте, в ТМА, в CLI.  
Никакого vendor lock-in — Telegram опционален, не обязателен.

## Контракт мира (World Manifest)

Проектируется после написания фермы методом extract & generalize.  
Примерная структура (уточняется по реальному коду):

```json
{
  "id": "world_abc123",
  "name": "Моя ферма",
  "official": false,
  "genre": "farm",
  "script": "main.lua",
  "assets": ["farm.glb", "trees.glb"],
  "physics": "3d_simple",
  "camera": "third_person",
  "gravity": 9.8,
  "max_players": 16,
  "permissions": {
    "visitors_can_edit": false,
    "age_rating": "all"
  }
}
```

**Спаун** — тот же формат, только `"official": true` и `"deletable": false`.

## Federation (Self-hosted серверы)

Минимальный API который должен реализовать каждый сервер:

```
GET  /info           → название, версия, онлайн, описание
POST /auth/verify    → проверить JWT с основного сервера
WS   /game           → игровой WebSocket
GET  /world/meta     → превью мира для реестра
```

```
Основной сервер ведёт реестр:
  пингует каждый self-hosted сервер раз в минуту
  показывает статус онлайн/оффлайн
  игрок кликает → клиент переподключается к новому адресу
  JWT путешествует между серверами
```

Деплой self-hosted: `docker run` — одна команда, сервер готов.

## Экономика

```
Глобальная валюта  → центральный сервер, под контролем разработчика
Локальная валюта   → своя монета на self-hosted сервере
Конвертация        → по курсу который устанавливает разработчик
```

Roblox-модель (Robux только через платформу) как вдохновение,  
но с возможностью локальных экономик на своих серверах.

## UI архитектура

### Desktop (нативный клиент)

```
raylib рисует 3D сцену
    +
Sciter рисует HTML/CSS панели в текстуру
    ↓
DrawTexture поверх сцены
```

Взаимодействие:

- мышь над панелью → события идут в Sciter
- мышь вне панели → raylib управляет камерой
- HTML кнопка → `sciter.call("onAction")` → Zig функция

### Web (WASM)

```
raylib (WASM) рисует в <canvas>
    +
обычный DOM (HTML/CSS) поверх canvas
```

Sciter не нужен — браузер сам рисует DOM. Тот же HTML/CSS кит.

### Встроенный браузер (опционально)

Системный WebView для полноценного браузера внутри игры:

- SoundCloud, YouTube, любой сайт
- drag & drop объектов из браузера в 3D сцену
- Edge WebView2 (Windows) / WKWebView (macOS) / WebKitGTK (Linux)

## Sandbox безопасности (Lua скриптинг)

Запрещено технически, без исключений:

- доступ к файловой системе сервера из скрипта
- сетевые запросы наружу (только внутренний API платформы)
- бесконечные циклы без `yield`
- превышение лимитов CPU / RAM на мир
- доступ к данным других игроков без явного разрешения

Всё остальное — на усмотрение создателя мира.  
18+ контент разрешён с меткой. Реальные деньги — только через платформу.

## Cold Start стратегия

Главная проблема платформ — пустой маркетплейс.  
Решение: контент от разработчика до прихода пользователей.

```
1. Спаун (официальный мир) готов до релиза
2. Официальная ферма — написана на тех же инструментах
3. Первые пользователи видят живой мир, не пустоту
4. ТМА даёт Telegram-аудиторию и retention
5. Пользовательские миры появляются постепенно
```

## Оценка рынка

- UGC-платформы растут: выплаты разработчикам +47% в 2025 году
- Взрослая аудитория — незакрытая ниша (Roblox = дети)
- Federation/self-hosted — уникальное позиционирование
- Прямые конкуренты Roblox испытывают трудности с cold start

**Для инвестиций нужны:** живые пользователи → retention → экономика.  
Инвестиции до этого нереалистичны.
